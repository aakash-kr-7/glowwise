## Methods and limitations

Resource creation was via official CLI/ARM with normal account authentication. Readbacks were saved privately and reduced to the public configuration JSON. The first Standard-security deployment failed on a subscription feature requirement; Trusted Launch succeeded using the same resource names. Cost estimate was written before successful VM creation; its earlier approximate-time label was corrected transparently. Actual cost reports had no rows yet; [ledger](../../Deployment/COST_LEDGER.md) records positive modeled exposure and lag instead of calling the deployment free.

TLS probes connect to the actual origin and resolver-returned edge addresses while preserving SNI and certificate validation. This avoids the operator's temporary negative local DNS cache without bypassing TLS checks. Credentials were loaded only from the restricted handoff in process memory. HTTP bodies were hashed/inspected for bounded acceptance predicates and never retained. Administrator session values were not logged. Direct-origin authentication protects bypass access as well as the CDN path.

Caddy automatic renewal is configured and certificate storage survives restart, but no renewal cycle has elapsed. Daily provider deallocation/guard thresholds are configured/read back; a threshold was not forced or destructive deletion tested. Backup validation proves an isolated SQL/file restore of the fresh installation, not a completed product or sanitized UpdraftPlus/Drive submission. Product implementation, public CDN HIT, CWV, analytics/indexing, live keyword demonstration and formal ten-criterion packaging remain separate gates. No marks are self-awarded.
