# Stage 2 — Azure, WordPress, DNS and HTTPS foundation

9 October 2026. Final infrastructure checks were captured around 10:50–11:10 UTC / 16:20–16:40 IST; each artifact has its own timestamp. This is an actual **protected fresh WordPress installation**, not the finished Glowwise product. The original readiness/access observations remain historical and unchanged.

## Implemented architecture and access

Cloudflare Free DNS/CDN and edge TLS → Caddy Let's Encrypt origin TLS → official WordPress Apache/PHP → MariaDB on an internal Docker network, on one Azure Linux VM. Source/development/builds run at `/srv/glowwise/source`; theme and separate `glowwise-core` locations are reserved. No replacement hosting platform or local website runtime was introduced.

The authenticated Azure account has Owner access to an Enabled Azure for Students subscription, with spending protection **On**. Normal device-code CLI authentication used the existing account; no browser tokens were extracted. The official portable Azure CLI is 2.91.0 and its state is private. Authenticated Cloudflare browser access works. Rediscovery found no callable Azure/Cloudflare connector in this session, so the official CLI and authorized browser completed the work; no unavailable plugin result is claimed.

Enforced regions: Malaysia West, India South Central, Poland Central, Korea Central and Indonesia Central. Initial usage/quota checks found total vCPU 0/6 and Basv2 0/10. In Korea Central B1s was restricted; **B2ats v2** had no SKU restriction and actual deployment succeeded. Historical failures in other draft configurations did not establish global unavailability. ARM was not chosen. The x64 Ubuntu image and AMD64 manifests of all four application/tool images and Node build image were checked.

`glowwise-dev-rg` contains one Korea Central `glowwise-vm` (**Standard_B2ats_v2**, 2 vCPU, 1 GiB), one 32-GiB Standard SSD LRS OS disk, Standard static regional IPv4 **20.249.61.80**, NIC/NSG/VNet/subnet and a daily shutdown schedule. Trusted Launch, Secure Boot and vTPM are enabled. No paid marketplace image, Bastion, NAT Gateway, load balancer, managed database, backup service or paid monitoring was created. Project/publisher/environment/limit tags identify ownership; exact IDs remain private.

The initial Standard-security deployment was rejected because this subscription required a feature for that security type. The final template uses supported Trusted Launch and reused the existing named network resources; it did not create a duplicate VM. NSG exposes TCP 80/443 and SSH only from the current operator /32. When the operator IP changed during the session, the restricted rule was updated and SSH reverified. Non-root key access and pinned host identity work; password/root/keyboard-interactive access is disabled. Security updates, unattended security updates without automatic reboot, 2-GiB swap, memory limits and bounded container logs are configured. A second reboot activated a later unattended kernel update; all services recovered and no reboot notice remained.

## Domain, certificates and caching

The zone is active on Free. Both authoritative nameservers and 1.1.1.1/8.8.8.8 confirm delegation to angela/trace and proxied apex/www addresses. Initially there were no existing records; apex A and www CNAME were added DNS-only for issuance and subsequently switched to Proxied. Legitimate unrelated records were not removed. No mail service/contact address is inferred from the dashboard's email recommendation.

Caddy explicitly uses Let's Encrypt ACME with persistent certificate data and automatic renewal. Origin apex/www certificate SANs and trusted chains were independently verified; they expire **7 January 2027, 03:07 UTC**. Cloudflare Universal SSL is active; its currently served edge certificate covers apex and wildcard and expires 7 January 2027, 02:03 UTC. Full (strict) is saved, minimum TLS 1.2 selected, TLS 1.3 on. HSTS/preload is disabled. HTTP and HTTPS www redirect directly to HTTPS apex without a loop; admin login redirects preserve HTTPS. Caddy, not Certbot, performed issuance. No elapsed renewal cycle or forced production renewal test is claimed. The rubric interpretation/fallback stays in [decisions](../Implementation/DECISIONS.md). [Caddy renewal mechanism](https://caddyserver.com/docs/automatic-https), [Cloudflare Full strict](https://developers.cloudflare.com/ssl/origin-configuration/ssl-modes/full-strict/).

Cloudflare uses Standard caching, Respect Existing Headers and one active dynamic/private bypass rule. It excludes writes, authorization/session cookies, admin/login/API/contact, query strings and non-static paths. Development headers are `private, no-store`; tested homepage, login, REST and assets are DYNAMIC, not a claimed CDN HIT. Public static caching will be tested when launch permits public assets. No blanket cache-everything rule exists. Retired Cloudflare Auto Minify was not enabled: VM build-time esbuild minification was actually verified on JS/CSS fixtures, with no product assets yet. [Cache behavior](https://developers.cloudflare.com/cache/concepts/default-cache-behavior/), [deprecations](https://developers.cloudflare.com/fundamentals/api/reference/deprecations/), [esbuild minify](https://esbuild.github.io/api/#minify).

## Cost and recovery acceptance

The Linux B2ats v2 750-hour benefit is expected from the matched free-services panel, not credited as proof of a zero invoice. No disk/Standard-IP benefit was assumed.

An annual US$8 budget has actual US$2/4/6/8 notifications and a forecast US$6 notification. Daily midnight-IST Azure deallocation, a 15-minute managed-identity guard (US$6 conservative exposure, seven-day lease, 10-GiB measured outbound) and a separate lifetime ledger provide practical controls. Spending protection stays On. Alerts are delayed; no custom hard US$10 cap exists. Deallocation retains about US$0.2104/day disk/IP plus transactions. No automatic deletion or lease extension is configured. See [ledger](COST_LEDGER.md) for dated exposure and lifecycle review.

Checksums, isolated file restoration, selected SQL table counts and the retained noindex option passed; the live database was not replaced. The restricted off-VM archive passed inner checksum verification. UpdraftPlus/public coursework backup remains a later task.
