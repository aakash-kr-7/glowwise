## Certificate wording and compatible fallback

The handbook says “Install SSL via Let's Encrypt / Certbot” (extracted paragraph P36); its excellent VPS descriptor asks for SSH setup, functional WordPress and command logs. It does not separately name Certbot in that descriptor. **Interpretation:** documented Let's Encrypt issuance through Caddy addresses the named CA and automatic HTTPS requirement; the slash is ambiguous and instructor acceptance cannot be guaranteed by this plan. No reason has been found to replace Apache/Caddy with Nginx.

If the instructor explicitly requires Certbot, retain Compose/Apache/MariaDB/Caddy and change only certificate management after recording the owner decision: run Certbot `certonly --webroot` with a shared challenge directory, route `/.well-known/acme-challenge/` from Caddy's HTTP listener to that directory, mount the issued PEM files read-only in Caddy, and schedule renewal plus a successful-renewal Caddy reload. Bootstrap through HTTP before loading absent certificate files; avoid competing ACME managers for the same host. Verify renewal and origin chain. This is a concrete alternative, **not implemented**. Sources: [Certbot webroot](https://eff-certbot.readthedocs.io/en/stable/using.html#webroot), [Caddy manual certificate loading](https://caddyserver.com/docs/caddyfile/directives/tls).
